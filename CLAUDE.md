## Lições e Aprendizados

### Lição Crítica de Arquitetura — Prisma e Edge Runtime

- PRISMA NUNCA pode rodar no Edge Runtime. O callback jwt/session do Auth.js v5
  roda no Edge. Uma tentativa de validar "user existe no banco" dentro do
  callback jwt quebrou o login de TODOS os usuários (JWTSessionError:
  "PrismaClient is not configured to run in Edge Runtime"). Foi REVERTIDO.
- Regra: nenhuma chamada Prisma em callbacks do Auth.js. O tratamento de sessão
  inválida / P2025 pertence a Server Component (Node Runtime), não ao Edge.
- Recomendação pendente: separar auth.config (edge-safe) de auth (node) para
  remover o PrismaAdapter do bundle do middleware.

### Lições Operacionais de Banco

- Para confirmar QUALQUER estado de conta/barbearia, usar SEMPRE o Neon SQL
  Editor (consulta ao vivo). NUNCA confiar no Prisma Studio para isso: ele mostra
  um snapshot em CACHE e não auto-atualiza (já causou falso diagnóstico de
  "conta deletada").
- IDs cuid contêm caracteres visualmente ambíguos (l vs 1, 0 vs O). Digitar id
  à mão em WHERE causa falso "No result". Padrão seguro: consultar via subquery
  por ownerId/slug (ex.: WHERE u.id = (SELECT "ownerId" FROM barbershops WHERE
  slug = '...')), nunca id digitado.
- Operações destrutivas (DELETE) em conta: SEMPRE rodar SELECT de barbershop e
  membership ANTES, confirmar que a conta não tem dados, e só então deletar.
  Distinguir conta vazia (onboarding incompleto: sem barbershop, sem membership)
  de conta real (tem barbershop/dados).
